# Tasks: sync-observation

Scope: the observation surface the sync tests read — the store's ordered subscription and session event, the runtime's numbered pod records, observed join and record listing behind `test-util`, the laptop host's `observation` build, pod interval and build profile, and the phone's test build. Groups 1 to 3 are what the load tests need (`load.md`, `plan.md` tasks 2b and 4a–4b for the load tests' share), ordered so the laptop-only test can run after group 2; groups 4 and 5 are what the reliability test alone adds. Group 3 opens with the network spike (`plan.md` step 1, task 3.1), and the rest of groups 3 and 5 waits on it. Every scenario test states in its doc which mechanism, removed, makes it fail, and was run once with it removed.
