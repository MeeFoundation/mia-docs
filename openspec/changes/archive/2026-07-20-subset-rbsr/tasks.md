# Tasks: subset-rbsr

Scope: capability-filtered reconciliation enforcing Invariant 2 — a serving node reveals only claims the peer is read-authorized for. Includes a minimal single-link read capability (precursor to UWill), and keeps grantees — capability-scoped and whole-store — outside the gossip swarm. Modifies pdn-store. The reconcile-trigger live path is a separate change (`reconcile-trigger`).

## 1. Read capability (data-layer)

- [x] 1.1 Minimal read-grant type: `{ issuer, audience, claims, commands }` — exact `ClaimId` set; `read` always granted, `write` optional, mirroring UWill's flat command set (no chain, no prefixes/geometry; D3)
- [x] 1.2 Interim claim identity: `ClaimId` derived from (issuer, entry path) via a domain-separated key-derivation hash (D3); evaluation always goes key→id→set membership, never id→location
- [x] 1.3 Issuance: an issuer grants an audience read (optionally + write) on a set of claims; the grant record's ticket is minted to match — read-only → `ShareMode::Read`, with write → `ShareMode::Write` (D11)
- [x] 1.4 Per-entry evaluation from the caller's effective grants; own-identity → authorized without a grant
- [x] 1.5 One width-tagged grant record per issuer: `grants/<issuer-hex>` replaces the ticket+capability slot pair — publish of either width replaces wholesale, withdrawal is one tombstone, and the classifier derives width only from a present decoded record (absence, replication lag, and undecodable payloads all classify as no grant; the tag is the structural format version). Recipient reads are variant-selective; `withdraw_scoped_grant` folded into the one `withdraw_grant` (delta: `data-layer-connection-metadata-store`)

## 2. Egress filter (pdn-store)

- [x] 2.1 Session-scoped filtering adapter implementing `ranger::Store` over an entry source plus the peer's rights frozen at session setup; reconciliation reads entries only through it (D6 — verified: `initial_message`/`process_message` are default methods of the trait, so the adapter is structurally the only door; `get_first` filtered too, or the initial range boundary would leak an unadmitted key)
- [x] 2.2 Filter coverage is uniform by construction — fingerprints, split boundaries, offers, and item transmissions all derive from the adapter's iterators; existence-hiding asserted in the scenario test after a proven second replication wave (the transcript-level property test stays post-demo, per the property-test plan)
- [x] 2.3 fs sessions read through a redb snapshot (`snapshot_owned`): snapshot opens at session setup and closes at `SyncFinished`; verify the two redb items from D6 (read transactions pin pages — keep lifetimes within session bounds; `snapshot()` commits an open write transaction — check the write-batching interaction)
- [ ] 2.4 Optional, when a profile demands it: materialized per-audience view keyed by the rights set, invalidated incrementally by the audience-resolution index (D6)

## 3. Wiring (data-layer + pdn-node)

- [x] 3.1 Serving side classifies the caller per replica: own device (directory) / counterparty device (published device sets, D9) / stranger; loads the caller's effective grants from the identity's own connection-metadata replicas (D8) and freezes the session filter (role-aware: a scoped holder refuses callers it cannot resolve but dials out with a closed egress — D10 note)
- [x] 3.2 `SyncNode` reconciliation uses the filter; the replica identity's devices and connection-metadata audiences get the full view; no computable rights → `Reject(NotFound)`, uniform with not-hosted (D10); enforcement armed per identity by `host_identity`/`host_connection` registration (D10 note — unregistered assemblies stay legacy ticket-bounded)
- [x] 3.3 Device-set publication (D9): establishment publishes the establishing device into the new `own` store, and every device that opens the pair asserts itself once (assert-once since 3.7 — a live record is untouched, a tombstone is never overwritten by opening) — so a linked device becomes resolvable the moment it first touches the connection, with no separate linking cascade; creation and linking arm classification (`host_identity`), pair assembly and opening register it (`host_connection`); the scoped grant surface (`publish_scoped_grant` / `read_scoped_grants`) and the scoped import (`import_scoped`) ride the services
- [x] 3.4 Reconciliation schedule for scoped peers (D7): a **before-access** nudge (non-blocking: reads/lists of a scoped namespace fire a filtered reconciliation and serve the local replica) plus the node's periodic reconcile pass (spawn-tunable, default 10 seconds — well inside the hourly baseline; scenario tests inject a sub-second cadence so refusal assertions wait out intervals, not wall-clock tens of seconds), which re-syncs scoped docs without joining gossip. The writer-side push (`reconcile-trigger`) is deferred.
- [x] 3.5 Linking arms before it imports: `link` registers the identity for classification the moment its directory is imported and before the data namespace is — the other order holds the namespace in the ticket-bounded stance (full to any caller) for the whole catch-up wait, on a long-lived id every past grantee knows. Failure rollback disarms (`unhost_identity`, the inverse of `host_identity`); callers the still-converging directory cannot resolve are refused fail-closed and re-served once their records land (delta: `pdn-node-device-linking`)
- [x] 3.6 The grant surface refuses foreign issuers: `publish_grant` / `publish_scoped_grant` refuse `identity != issuer` with a typed error (`DelegationUnsupported`) — the classifier scans the data issuer's own connections (D8/D9), so a foreign-issuer grant would publish fine, replicate, and be honored by nothing, silently, on both sides. Interim boundary, not a model decision: keying by issuer stays as the delegation groundwork, and the boundary lifts with `UWill` chains (delta: `pdn-node-core`; refusal test beside the allowed grant in the `establishment` suite)
- [x] 3.7 Device records assert once: pair opening — `open_pair` and establishment's assembly — publishes through `ensure_device_published`, a no-op when any record exists, live _or tombstoned_ (`include_empty` probe), so a withdrawn device is never re-asserted by machinery and the documented read paths stop writing; deliberate re-assertion stays `publish_device`. Enforced revocation (write-authority rotation) and the per-identity author are deferred with UWill — recorded in D9. Rode along: the before-access nudge is debounced to one in-flight attempt per namespace (an undebounced 120-second poll spawns up to 1,200 tasks against one replica), and `forget_namespace` drops the doc before unregistering (closing the two-hop alive-but-unknown window)

## 4. Grantees outside the swarm (pdn-store)

- [x] 4.1 Scoped access does not join the replica's gossip swarm: the scoped import/session path skips gossip subscription (`start_sync_scoped` through the whole api chain; the periodic reconcile pass keeps scoped docs scoped), while same-identity devices stay swarm members
- [x] 4.2 Whole-store grant imports stay outside the swarm too: the granted import shares the scoped import's contacts-only path — registration before first sync, rollback on a failed start — and a post-import write from an armed issuer does not reach a bare-ticket holder (probed by the pdn-node `data` suite)
- [x] 4.3 Membership follows the strategy in both directions: the fork gains `leave_gossip` — quit the topic (both subscription halves drop, broadcasts stop in both directions) while the replica stays open, syncing, and subscribed to; a grantee import calls it, so downgrading a device-replicated replica to a grantee binding _leaves_ the swarm instead of membership outliving the strategy, and the import rollback restores the displaced tracking entry and re-aligns membership with it (without that, a failed link over a granted namespace leaves the grantee's replica in the swarm). Rode along: data imports refuse tickets naming device-shared replicas (directory / connection metadata) — repurposing their tracking, and with it their swarm membership, must not be reachable by a minted ticket. Probed by a fork test (`sync_leave_gossip_keeps_sync_running`)
- [x] 4.4 Content-free swarm (fork): the topic no longer carries entries. A local insert broadcasts a content-free author-head announce (`Op::SyncReport`, via `broadcast_local_head`) to neighbors instead of `Op::Put(entry)`; the receive path drops `Op::Put` (never inserts it); content flows only over the classified reconciliation the announce triggers (`on_sync_report → has_news_for_us → sync_with_peer`), cascaded per hop exactly like the post-sync report. A data-namespace topic subscriber therefore gets only activity metadata, never keys/hashes/values; the reconciliation is gated so an unresolvable caller gets nothing. `Op::ContentReady` left untouched by decision (blob-egress-by-hash deferred). Subsumes 4.3's content half: swarm membership no longer conveys content, so `leave_gossip` becomes a metadata/resource measure; the downgrade canary is rewritten to `swarm_membership_does_not_bypass_the_access_book` (a persistent swarm member is served only while its grant stands — the D5 "membership outlives revocation" property, now enforced). Fork pre-push checklist green (incl. `sync_gossip_bulk`, `sync_leave_gossip_keeps_sync_running`); own-device propagation confirmed by `sync_two_devices`/`three_devices`/`multi_identity`

The reconcile-trigger live path (resolve covered peers, send, coalesce, triggered-peer-reconciles) is the `reconcile-trigger` change.
