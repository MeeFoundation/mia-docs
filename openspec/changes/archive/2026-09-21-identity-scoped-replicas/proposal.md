# Identity-scoped replicas

## Why

A node hosts the store sets of any number of identities, and co-location is not a trust boundary: two identities of one person are as separate as two strangers ([operating-conditions](../../specs/code-practices/operating-conditions.md)). The node does not hold them apart. One replica per namespace, one author per node and one classification keyed by node id mean that what belongs to two identities is stored together, written under one name, and told apart only by a check at each point that reads it.

Three consequences are recorded across the tree. A node hosting two audiences of one issuer binds one replica and receives the union of both grants into it, and a local read of that replica answers from the union, because it is addressed by issuer and carries no acting identity. Every store on the node writes with the node's one author, so on a shared node two members of one cell publish the same author key, an entry passes as either member's, and a membership act resolves to two actors at once — the open question F2 of the cells change. And a grant withdrawn toward one audience leaves the other's replica holding what the first one received, because the bytes were never separate.

This change makes the separation structural, at the level ADR-0013 states. A hosted identity comes to own its replica store, its author and its sessions, so isolation follows from where the bytes live rather than from a filter applied on every read. The same step settles what subset-rbsr deferred as the per-identity consumer view.

## What Changes

- **A hosted identity owns its replicas.** One replica store, one persisted author and one set of registered replicas per hosted identity, over the node's shared endpoint, gossip and blob store. Two identities granted by one issuer hold two replicas of that issuer's namespace, each with its own contacts and its own rights.
- **A sync session names the identity on both ends.** **BREAKING** The docs protocol carries, as opaque identities, the identity of the replica being addressed and the identity the caller acts as. A node may name only an identity whose device set lists its node id; naming any other is refused as not hosted. Rights come from the named identity alone and are never unioned across the identities a node hosts.
- **Ingest and egress are judged per hosted identity.** Write admission is recorded per hosted identity, namespace and caller, and the egress filter serves what the named identity's grant covers.
- **Every replica is created and imported for a named identity.** **BREAKING** A create and an import name the identity the replica is held for — the private metadata directory and the connection metadata stores included — and a ticket landing anywhere but with the identity its grant record addressed is refused.
- **Writes name the identity performing them.** **BREAKING** The data service takes the acting identity, and each hosted identity writes with its own author, stable across restarts. What a device is, as a cell or a counterparty sees it, becomes the pair of the device and the identity.
- **Two identities of one node talk inside the process.** iroh refuses a connection to the node's own endpoint, so co-located identities cannot reach each other over the network at all. Sync sessions and the pairing dialogue between two identities of one node run the full protocol over in-process streams, with both sides classifying, gating and filtering exactly as over the network, and with a write announcing to co-located identities directly, since a node's own gossip broadcast never reaches its other subscribers.
- **The replica store's cache size becomes configuration, as a budget the node cuts into shares itself.** The cache is bounded per store and the bound is fixed when the store opens, so a node is spawned with the memory its replica stores may hold together and nothing else: each identity's store is bounded at that memory divided by the identities the storage directory records as hosted when the store opens. One stated default of 1 GiB serves the hosts and the suites, a device carrying a single identity gives it the whole budget, and a node whose bounds handed out together pass its budget — a node that grew while it ran — reports it until the next start cuts every share from the whole set. A host on a phone is expected to state that one number at that application's first start, which this change states and does not implement.
- **Nothing is served without an owner and a verdict.** **BREAKING** Every replica is held for an identity the node hosts, and the store takes its session access provider as a requirement of assembling it rather than an option that defaults to serving whole. A data replica whose identity holds no records to judge a caller by is refused; a directory and a connection metadata store keep their ticket bound under Invariants 1 and 3.
- **The node's storage directory holds one subdirectory per hosted identity, and each records its own hosting.** **BREAKING** The node's one `hosted-identities.json`, which disk-persistence introduced, goes: an identity's subdirectory carries its hosting record, the namespace of its private metadata directory, written at the commit point of the create or link, and a start re-hosts every identity whose subdirectory holds one. A record skipped at a start stays for the next, and a subdirectory an unfinished create or link left hosts nothing and takes no share of the cache budget. Nothing reads a directory written under the previous layout, and no migration carries one over.

## Capabilities

### New Capabilities

- `components/mee-pdn/data-layer/identity-scoped-replicas`: the ownership model — a hosted identity owns its replica store, author and registered replicas; the identity named on each session and how a caller's claim to act as an identity is checked; rights per identity with no union; the import rule; what a node that hosts several identities can and cannot obtain.
- `components/mee-pdn/data-layer/in-process-sessions`: the path between two identities of one node — when it is chosen, that it runs the same protocol with the same gates, the announcement that reaches co-located identities, and the reconcile pass that does not open a session per interval with nothing to carry.

### Modified Capabilities

- `components/mee-pdn/data-layer/multi-identity`: isolation between identities on one node becomes structural rather than classified per session, the identity replaces the node as what a session resolves to, and the replica a node holds under no identity — served whole to any holder of its ticket — goes.
- `components/mee-pdn/data-layer/subset-reconciliation`: the caller's rights are resolved for the identity it names instead of every identity its node id resolves to, a granted replica's contacts are addresses paired with the identity each is dialed as, and a retraction's marker reaches the directory of the identity that wrote the entry alone.
- `components/mee-pdn/data-layer/capability-gated-ingest`: the write set a session freezes is recorded per hosted identity as well as per replica and caller, and no replica outside every identity is left to admit whole.
- `components/mee-pdn/data-layer/write-retraction`: a verdict's marker is recorded in the directory of the identity that wrote the retracted entry, which the verdict's author names, rather than in every co-hosted audience's directory.
- `components/mee-pdn/data-layer/durable-storage`: the author becomes one per hosted identity rather than one per node, the directory holds a subdirectory per hosted identity carrying its hosting record, and a store's share of the cache budget is cut from the identities the directory records.
- `components/mee-pdn/data-layer/node-assembly`: the docs protocol dispatches an accepted connection to the identity its first message names, while the endpoint still carries all protocols.
- `components/mee-pdn/pdn-node/namespace-addressing`: one namespace per issuer stands, and a node holds one replica of it per hosted identity that acquired it.
- `components/mee-pdn/pdn-node/core`: the data service takes the acting identity; a granted replica's contact set follows the one connection that bound it, so the requirement that unions every co-hosted audience's siblings and issuer devices is replaced; a grant binds and unbinds for the identity it addresses, so the replica leaves with that one grant and the count of bound pairs that kept a shared replica alive goes with the sharing.
- `components/mee-pdn/pdn-node/connection-establishment`: two identities of one node establish a connection through the same dialogue, run inside the process.
- `components/mee-pdn/pdn-node/device-linking`: a failed link drops the stores it brought up for the identity it joins and reaches no other identity's replica of the same issuer, so the rollback stops restoring a displaced binding; what it leaves on disk is hosted by no start.
- `components/mee-pdn/pdn-node/restart-recovery`: recovery restores each hosted identity with its own stores and author, from the hosting record in the identity's own subdirectory; a record whose replica is missing is skipped and left as it is, and a record whose store is gone opens none.
- `components/mee-pdn/pdn-node-http/host`: a data operation addresses the acting identity as well as the issuer.
- `components/mee-pdn/pdn-node-http/container-stand`: read isolation between two identities on one node becomes assertable, and the stand asserts it.

## Impact

- **`crates/pdn-store`**: the session access provider required rather than optional, the cache bound a replica store is opened with, the identity fields on the protocol's first message, dispatch of an accepted connection before the engine is chosen, the identity handed to the session access provider, contacts carrying the identity they are dialed as, the announcement carrying the identity of the replica that wrote, an entry point for a session over in-process streams, the engine's requests about co-located identities handed to its node on a channel, and the task serving an engine's API owned by the engine's protocol handle. The replica store's own tables, the open-replica map, the live state and the range reconciler are untouched. The sync actor carries the session's ingest verdict from its setup to the gate, beside the egress filter it already carries, so the write set a session freezes holds for that session and no longer; the divergence from upstream is otherwise the protocol boundary, that one parameter on the open path, and this one on the session path.
- **`crates/data-layer`**: a hosted identity owning an engine, a registry and an access book; the displaced binding and displaced tracking an import returns for the link rollback, which a registry per identity leaves nothing to displace; the classification of a data replica the book knows nothing about turned from serving it whole into a refusal; the check that a caller's node id appears in the device set of the identity it names; the import rule; the author per hosted identity; the routing rule that sends a dial to this node's own address through the in-process path; the identity named at every create and import, the private metadata directory and the connection metadata stores included; the hosting record each identity's subdirectory carries, written at the commit point and listed at a start, and the budget share counted from the identities recorded; a task of the node serving the engines' co-located requests, holding the identity map weakly; and a shutdown that releases every engine, the blob store and the directory lock whatever the router answers.
- **`crates/pdn-node`**: the acting identity on the data service; the pairing dialogue generic over its streams so it runs in-process; contacts derived per identity; recovery per identity, from each identity's hosting record, with the node-wide `hosted-identities.json` and its writer gone; the grant binder deciding from the pair it swept — the check whether another pair still holds the issuer, and the derivation across every pair bound to it, go; the retraction verdict recorded in the one directory its author names; the link rollback dropping what it brought up, with the displaced binding it used to restore gone.
- **`crates/pdn-node-http`**: the debug data routes carrying the acting identity.
- **Tests**: the `data-layer` suites that reconcile a replica between two nodes holding no identity arranged the product's way — the identity hosted, the second device in its device set — and the store's own suites naming the permissive provider they used to get by default; the data service's callers updated for the acting identity; the four scenarios in `pdn-node/tests/reachability.rs` that rest on one replica shared by two audiences — three rewritten to the separated expectation, each keeping its paired denial, and the one that pins the count of bound grants against the binder's bookkeeping removed with the count it pins; the three author scenarios in `data-layer/tests/persistence.rs` restated per identity; new scenarios for two identities of one node establishing a connection and converging a shared namespace without the network, and for a node that names an identity it is not a device of, which needs a fixture that names an identity of its own choosing, behind `test-util` as `write_unguarded` is.
- **Other changes**: cells gains a device that is the pair of device and identity, holds a cell twice on a node two of whose identities are members of it, and loses the co-hosting half of its open question F2; reconcile-trigger carries the identity in whatever transport it settles on; mobile-host-surface exports the acting identity with the data operations and takes the cache budget and identity count its application states.

## Out of Scope

- **Blob egress.** A provider still serves any hash to any caller that asks, so payload bytes are not bound to an identity. The gate arrives with the identity-bound authorization work.
- **Unlinkability of identities on one node.** One endpoint means one node id in the device sets of every identity the node hosts, so a counterparty of two of them sees the same node id in both. This change isolates what is stored and who wrote it, not who is observed together, and separating the node ids is what an endpoint per identity would take.
- **Identity-level authentication of a session.** The claim to act as an identity is checked against that identity's device set, which is what the node id already carried. A cryptographic proof needs identities to hold key material.
- **Cells.** Nothing here decides membership, roles or the cell stores; it decides which identity holds them.
