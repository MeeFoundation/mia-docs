# Proposal: direct-device-linking

## Why

Device linking is the last ceremony whose critical path rides the replication machinery: the seed QR carries a durable write ticket to the identity's whole directory (a photographed QR grants write access forever — a `DocTicket` never expires), and `link_device` then waits on reconciliation twice — once to discover the connections-store ticket through the directory, once to push its own device registration back to an existing device — each wait a retry loop born from a debugged flake. Establishment (ADR-0011) already demonstrated the shape that avoids all of this: a raw dialogue on a dedicated ALPN, a one-time secret atomically verified-and-burned, state committed by the party that owns it before the reply. This change rebases linking onto that shape and removes the structural reasons for both waits — agreed with the lead (16-07): reconciliation is a procedure with traps, so the linking handshake should not depend on it at all, and the two device-internal replicas should become one so "the directory synced but the connections store silently didn't" stops being a reachable state.

## What Changes

- **The connections store folds into the private-metadata directory.** Connections become `connections/<pdnid-hex>` records in the directory next to `devices/` and `tickets/`, semantics verbatim: one entry per counterparty with the identity in the key, opaque marker payload, tombstone disconnect, record-level liveness, last-writer-wins across devices. One replica now carries all of an identity's device-internal state — the two stores always had the same audience (Invariant 1), so the separation bought no isolation and kept alive a failure class where one replica syncs and the other silently does not. The `tickets/connections` directory kind dies with the store, and with it the linking-time discovery wait (`wait_for_ticket`): after importing the directory there is nothing left to discover. **BREAKING** for `data-layer`'s public surface (`ConnectionsStore` removed, `IdentityStores` reshaped) — pre-release, callers rewritten in place.
- **Linking becomes an establishment-style dialogue on a dedicated ALPN** (`/pdn/linking/0` — separate from pairing: the stakes differ, a whole-directory write ticket versus per-connection read tickets). The QR payload is bearer-free — format version, inviter device address, one-time secret, identity `PdnId` — mirroring the invite payload of ADR-0011. The new device dials and presents the secret; the inviter atomically verifies-and-burns it before any state change (uniform refusals: wrong, burned, expired, malformed all get the same silent close, and a refused attempt leaves nothing observable); the inviter then registers the new device itself, writing `devices/<node-id>` into its own replica — the newcomer's node id comes from the connection's authenticated peer identity, not from a claimed field — and replies with freshly minted write tickets over the encrypted channel. Commit precedes the reply, exactly as in pairing: a lost response leaves a registered-but-absent device record (harmless — device records carry no liveness semantics), and a fresh invite converges, like re-establishment. This kills `confirm_registration`, `PrivateMetadataStore::sync_with` (its only two callers were the two retry drivers), and `CONTACT_RETRY_INTERVAL`. What survives is the *wait* those loops were built around, promoted to a store primitive — see the surface bullet below; what dies is the hand-rolled retry cadence around it, now the node's periodic reconcile pass.
- **BREAKING: the identity service's linking surface is replaced.** `linking_seed` — the write-ticket handout — is removed. In its place: minting a linking invite for a hosted identity (one-time secret with a short lifetime, self-contained payload) and linking from a scanned payload; the payload names the identity, so the caller no longer passes it separately. `link` keeps the returned-means-caught-up contract: one bounded wait for the first successful directory sync session against the peer that just answered the dialogue — a single wait, not a retry loop.
- **The data namespace joins the bootstrap.** Identity creation provisions the data namespace (as today) and now also publishes its ticket in the directory under `tickets/data` — the flat model's stated exception: the identity's own data-store ticket lives in the directory. The linking reply carries a fresh data-namespace write ticket next to the directory ticket, and the linking device imports it, registering the namespace under the payload's identity. Induction: every device of an identity hosts its data namespace — the first device by creation, every further one by the linking reply. Manual out-of-band handover of same-identity data tickets disappears from scenario tests; ADR-0009's "discovery at linking is deferred" note is resolved by this change.
- **Against the change's overall subtraction, `data-layer` gains three methods the ceremony cannot run without.** `link`'s single catch-up wait is exactly today's confirmation-loop semantics — the first sync session that started after a chosen instant and succeeded — and today it rides a crate-private event subscription over a fork type `pdn-node` cannot even name, having no dependency on the fork. Rather than export the fork's event stream for one consumer, the directory states the property itself: a bounded wait for a successful sync session, plus the namespace accessor its metadata-store sibling already has. Separately, `import_namespace(issuer, ticket)` gains its counterpart `forget_namespace(issuer)` — untrack, drop, unregister as one act — because the rollback must leave the issuer unknown again, and dropping the replica alone leaves the registry still resolving it. Without these three the linking dialogue is unimplementable and its timed-out-link scenario unobservable (D8).
- **The linking procedure's spec moves next to establishment's.** The ceremony (provisioning on the first device, the linking dialogue on every further one) is pdn-node behavior and is specced as `pdn-node/device-linking.md`; `data-layer` keeps the store specs. A new ADR-0012 — device linking over a raw iroh connection — records the transport decision, mirroring ADR-0011's form and rationale.
- **Invariant 1 is reworded** (task-level edit; invariants are referenced by number): one device-internal replica instead of two, and its ticket handed to a new device over the linking dialogue after the verify-and-burn — no longer carried in a QR.

## Out of Scope (deferred)

- **KERI proof of control over the presented `PdnId`** — a marked step of the dialogue, deferred exactly as in pairing (ADR-0008's interim posture).
- **Offline / pending linking invites** — both devices online, as with pairing.
- **Device removal, revocation, unlinking** — the device set only grows for now.
- **The reactive bootstrap cascade** — watching the directory for new tickets and auto-importing what they point at remains its own change; the dialogue hands over the bootstrap tickets directly, and everything else (connection metadata pairs) still arrives through directory sync, opened on demand.
- **Deterministic derivation of per-connection replica namespaces** (the concurrent-establishment own-replica split) — ADR-level, separate.
- **Human-readable device labels in the registration payload** — pre-release, cheap to add later behind the payload's format version.
- **QR encoding and rendering** — the linking payload is a versioned value; its string/QR form is a host concern.

### New Capabilities

- `pdn-node-device-linking`: the ceremony — provisioning an identity's store set on its first device (directory + data namespace, both tickets published/held locally); the linking payload and one-time secret; the dialogue on the linking ALPN with atomic verify-and-burn; inviter-side device registration from the connection's authenticated peer identity; the reply carrying the directory and data-namespace write tickets; the returned-means-caught-up contract; lost-response convergence via a fresh invite; refusals that leave no observable state.

### Modified Capabilities

- `data-layer-private-metadata-store`: gains the connections records (the requirements folded in from the connections store: one entry per counterparty, tombstone disconnect, record-level liveness, last-writer-wins, replication between devices) and the `tickets/data` kind; the typed-tickets requirement loses the `connections` kind; the routing requirement's account of what the directory carries gains the connections records; and the store gains the namespace accessor and the bounded wait for a successful sync session that `link`'s catch-up contract and rollback stand on (D8).
- `data-layer-node-assembly`: the assembly hosts a second supplied handler — the requirement text and the endpoint requirement stop naming pairing as the only one, and ADR-0012 joins ADR-0011 as a protocol this registration point carries. Nothing normative changes: "zero or more" already admitted two, and the uniqueness requirement (distinct ALPNs) becomes load-bearing for the first time — pairing against linking is the first real pair.
- `data-layer-data-store`: gains the counterpart of registering a data namespace — forgetting an issuer's namespace so the issuer becomes unknown again rather than resolving to a dropped replica (D8).
- `pdn-node-core`: the identity-service requirement — creation provisions directory plus data namespace and publishes the data ticket; seed-based linking is replaced by the invite/link pair; the connections-service requirement — listing delegates to the directory's connections records instead of a dedicated store.
- `pdn-node-connection-establishment`: the establishment-outcome and re-establishment requirements re-target the directory's connections records (the assembly writes a directory record, not a connections-store entry).
- `data-layer-multi-identity`: the store-set enumeration shrinks to directory plus data store — per-identity isolation requirements unchanged in substance.
- `data-layer-connection-metadata-store`: the dedicated-replica requirement's enumeration of device stores shrinks to the directory.

### Removed Capabilities

- `data-layer-connections-store`: the whole capability — every requirement either folds into `data-layer-private-metadata-store` (entry scheme, tombstone, replication, last-writer-wins) or dies with the dedicated replica (the dedicated-replica requirement itself). The spec file is deleted on archive.
- `data-layer-device-linking`: the whole capability — the procedure moves to `pdn-node-device-linking` (reshaped around the dialogue); the store-level facts it carried (directory-first bootstrap, seed semantics) are superseded by the dialogue handing over the bootstrap tickets directly.

### Non-capability spec edits (tasks, not deltas)

- `components/pdn-node/invariants.md`: reword Invariant 1 — one device-internal replica (the directory), ticket handed over the linking dialogue, "either replica" phrasing dropped. Invariants 2 and 3 stay true verbatim (2 names no store at all; 3 names the directory and ticket routing, both of which survive), so the append-only list keeps its numbering.
- `architecture/adr/0012-linking-over-raw-iroh.md`: authored by this change (proposed), mirroring ADR-0011's form; records the transport decision, the bearer-free payload, inviter-side registration, and the tickets-in-reply bootstrap.
- Purpose-prose sweep for the removed store and the old seed flow: `data-layer/data-store.md` (store-set enumeration; the "discovering data stores during device linking is deferred" sentence is resolved by the linking reply), `data-layer/private-metadata-store.md` (the procedure pointer moves to `pdn-node/device-linking.md`; the directory carries connections records), `data-layer/multi-identity.md` (store set), `data-layer/connection-metadata-store.md` ("the mechanism the other device stores already use" — there is one such store now), `data-layer/node-assembly.md` (title and purpose: the registration point carries two ceremonies; its rationale — protocol-agnostic because the ceremonies' semantics belong in pdn-node, not because the assembly is a general protocol-extension facility — is reworded, not reversed).
- ADR corrections: ADR-0011 asserts twice that establishment writes a connections store — the after-the-dialogue summary, and the atomicity property "no connections-store write" — both re-grounded on the directory's connections records; ADR-0011's Related-ADRs list gains ADR-0012. ADR-0009 names `ConnectionsStore` among the device-internal stores. (There is no ADR-0009 deferral pointer to resolve: the data-namespace deferral sentence lives in `data-layer/data-store.md` and in the dying `data-layer/device-linking.md`, pointing *at* ADR-0009, not inside it.)
- `architecture/language/`: no edits. The glossary states the accepted connection model store-agnostically ("it exists as mutual state"), and no entry among the sixteen names the connections store, the seed, or device linking — checked, so that nobody goes hunting.
- `code-practices/flaky-tests.md`: the device-linking precedent records the confirmation loop in `link_device` as the *measured* cure for a flake at about 1.2% per linking act. This change removes that loop on a structural argument instead — inviter-side registration takes the cross-node delivery out of the critical path, so the race has no site — and the precedent gains a line saying which mechanism replaced it. History stays; a deleted cure must not read as still installed.
- Sibling-change sweep: `changes/subset-rbsr/` — `design.md` D4 enumerates "(connections store, private metadata store, data store)", and `proposal.md` (twice) and `tasks.md` name the `device_linking` suite as a verification obligation, a suite this change dissolves (procedure scenarios move to pdn-node, store-level ones fold into the store suites); all four updated to the post-fold store set and suite names, so subset-rbsr's acceptance stays runnable. `changes/reconcile-trigger/`: checked, nothing to do — its one store mention is swarm-generic.

## Impact

- **`crates/data-layer`**: `connections.rs` deleted; `private_metadata.rs` gains the connections surface (`connect` / `disconnect` / `is_connected` / `list_connections`) plus D8's namespace accessor and bounded sync-session wait (the wait keeps the crate-private event subscription behind it, so the fork's event type stays unexported and `pdn-node` keeps no fork dependency); `node.rs` gains `forget_namespace(issuer)` and `registry.rs` the unregister it resolves through; `linking.rs` deleted — provisioning and linking move to pdn-node, `link_device`'s waits (`wait_for_ticket`, `confirm_registration`) and the `sync_with` trigger with them; `lib.rs` / `registry.rs` / `node.rs` doc sweeps. Scenario tests re-target the directory's connections records (`sync_two_devices`, `three_devices`, `multi_identity`); `device_linking.rs`'s procedure scenarios move to pdn-node with the ceremony and its store-level ones fold into the store suites — including `directory_carries_arbitrary_tickets`, whose throwaway `"data"` label now names a real kind; `linking_times_out_without_connections_ticket` dies with the discovery wait. (`listing.rs` touches no device store — nothing to re-target there.)
- **`crates/pdn-node`**: a linking module next to `pairing.rs` (payload, wire messages, protocol handler and dial side, pending-secret bookkeeping shared with or parallel to `PendingInvites`); the handler registers at `Runtime::spawn` through the same assembly slot, alongside pairing; the identity service reshaped (**BREAKING** trait change: `linking_seed` out, invite/link in; `create` additionally publishes the data ticket); `assemble_connection` and the connections service's `list` re-target the directory. Tests: `linking.rs` rewritten onto the ceremony with paired denials per the access-control-tests practice (foreign secret, replayed/burned secret, expired secret, uniform refusal, no observable state after refusal — the boundary the QR-ticket model never had); `establishment.rs` / `connections.rs` / `common` adjusted to directory-backed connection records and the new linking API; `data.rs` scenarios drop manual same-identity ticket handover.
- **`crates/pdn-node-http`**: no linking surface today — no changes expected beyond compile checks.
- **`crates/test-utils`**: more than a doc-comment sweep — `wait_connected` takes a `&ConnectionsStore` and is re-typed onto the directory, along with its callers in `device_linking`, `three_devices`, and `sync_two_devices`; the `ids` module's doc comment names connections stores.
- **Dependencies**: none new — `postcard`, `serde`, `rand` are already direct `pdn-node` dependencies from pairing.
- **pdn-store fork**: untouched.
- **Flaky-test discipline**: the change ends with a counted stress pass over the affected scenario suites (linking, establishment, device-store replication) per `code-practices/flaky-tests.md`, before anything is built on top.
