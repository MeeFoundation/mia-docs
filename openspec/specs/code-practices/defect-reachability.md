# Defect reachability: what obliges a fix

A defect is fixed because someone can reach it, not because it exists. Three questions decide, asked in the order below. The order follows how obvious the answer usually is, not how much the answer matters: a yes to either of the first two obliges a fix, and the defect's severity — what it breaks — decides how urgent that fix is.

The rule covers defects in behaviour: what the code does when something calls it or sends it something. A violation of the repository's own rules — a comment in the past tense, an access test without its paired denial — is fixed because the rule it breaks says so, and reachability does not enter into it. When the code and the spec disagree, this rule classifies the behaviour the code lacks; and when the code does what is intended while the spec promises more, the fix is the spec, together with the design and the tasks that repeat the promise, not the code.

In a review every finding states which of the three it is, or that it is not a defect in behaviour, and names the path: the public operation and the circumstance for the first, the input a modified node sends for the second, and for the third why neither exists.

## Reached through the product path: fix

A defect is reachable through the product path when a host that calls the public surface of `pdn-node`, as its documentation states, can trigger it under some circumstance. The circumstances include every condition in [operating-conditions](operating-conditions.md): several identities on one node, a device that links in the middle of a process, a restart, a full disk, a connection that drops. `pdn-node` is an embeddable runtime, so its surface is everything it makes public, not only what the hosts in this repository export today: a host the project does not write may call any of it. The instruments behind the `test-util` feature are not part of that surface, because product builds do not contain them. Dropping what the surface hands out is a call like any other: a runtime dropped without `shutdown` while its process goes on, and a future dropped before it completes, are circumstances the surface has to survive, because any caller can produce them, a panicking one included.

## Usable by a modified node against honest nodes: fix, without exception

A defect is reachable over the network when a modified node — a node whose owner changed its code — can turn it into unauthorized access or a denial of service for honest nodes. A modified node controls everything about itself, so what it does to its own state is its owner's business; its only lever against others is what it sends: sync sessions and their messages, gossip, the tickets and grant records it writes, and the timing and number of its connections. Unauthorized access means data, or the fact that data exists, reaching a party without a capability for it, or an entry admitted past the ingest gate. Denial of service means an honest node, or one of its identities, losing the ability to sync, to serve or to accept sessions, or spending memory, storage or time without bound. Such a defect is fixed even when no honest node's product path ever produces that input, because the input comes from a node that does not follow the product path.

Two honest nodes that run different builds are outside this clause, because neither of them is a modified node. What a node owes a peer that still speaks an older wire format is decided by the change that alters the format, in its design, which records whether anything deployed still speaks the old one; this rule neither obliges compatibility nor excuses its absence.

## Reached neither way: fixing is optional

A defect that no host can trigger through the public surface of `pdn-node`, and that no input from a modified node can turn against an honest node, may stay unfixed. Such a defect usually sits in an internal API that the runtime never calls in the way that would expose it. Leaving it is a decision, and the decision is recorded with its argument: which callers reach that internal API, and why no input from the network reaches it. The decision is revisited whenever the surface changes — a new public operation, a new caller of the internal API, a host that starts exporting one more call — because each of those can turn an unreachable defect into a reachable one. A cheap fix that makes the defect structurally impossible is still welcome; this rule removes the obligation, not the option.

## Worked example

The store's share operation restarts a document's sync and, as part of that, restates whom every recorded peer of the document is dialed as, naming the identity that mints the ticket. On a replica held under a grant, whose recorded peers are the issuer's devices, that is reachable through the product path, because the data service's `share` is public; so sharing a namespace held as a grantee is refused (`GranteeCannotShare`, raised by `SyncNode::share_ticket` in `data-layer`). On a connection metadata store received from the counterparty, whose recorded peers are the counterparty's devices, the same restatement is reached by no public operation, because the runtime shares only its own half of a connection, and by no input from the network, because sharing is a local call. That one is left as it is, and the next reconcile pass puts the right identity back in any case.
